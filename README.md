These are **post-submission learning resources**. Complete the homework before opening the corresponding reference page.

## How to use these references

1. Complete and submit your own homework.
2. Re-read the assignment requirements before looking at a reference.
3. Pick a submission based on the specific technique you want to study.
4. Compare the author’s decisions, evidence, and tradeoffs with your own work.
5. Carry the lesson into a new problem instead of copying an artifact.

Good questions to ask while reviewing a submission:

- What evidence led the author to this conclusion?
- Which decisions were automated, and which required human judgment?
- How did the author test the boundary of a failure mode or evaluator?
- What would change if the dataset, policy, or model changed?

## What “selected” means

The collection is curated by the course team. A submission may be included because it offers strong evidence, a particularly clear explanation, a useful tool, an unusual method, or an honest negative result.

Selection does not mean that every implementation choice is endorsed. The references are examples rather than answer keys, and several good submissions may reach different conclusions.

Optional work is identified as such and is not used as a hidden requirement. Always follow the current assignment handout when it differs from an older submission.

## Links and preservation

Student code stays in the student’s repository and is linked at a specific pull request or commit when available. This preserves attribution and avoids copying solution code into this repository.

Video links currently point to the original submission. The course team may replace them with course-owned unlisted mirrors so the references remain available.
